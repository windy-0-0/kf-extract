# GUI 端到端回归（真浏览器）

## 为什么需要这一层

`tests/kf/test_gui.py` 只测**后端接口**和**模板结构**。它证明不了：

- 点「开始抽取」按钮真的会跑
- 任务历史点回去真的能恢复结果
- 图片真的加载出来了（`naturalWidth > 0`，不是"返回 200"）
- Esc 真的关掉了 viewer

这些只能靠真浏览器。**历史上这里吃过两次亏**：

1. 结果页 17 张图全 404，但 `curl` 每个接口都是 200 —— 因为 URL 编码错了
2. `str.format` 撞上 CSS 花括号导致首页空响应，但 `/api/*` 全正常

两次都是"接口没问题、界面不能用"。

## 怎么跑

```bash
# 1) 装依赖（只需一次）
cd tests/e2e && npm install

# 2) 跑（会自动起 GUI、跑完自动关）
node tests/e2e/run.mjs

# 指定浏览器 / 端口 / 素材
CHROME_PATH=/path/to/chrome KF_PORT=9000 node tests/e2e/run.mjs
```

依赖只有 `puppeteer-core`（**不下载 Chromium**，用你机器上已有的 Chrome/Edge）。

## 它断言什么

| 用例 | 断言 |
|---|---|
| 首页可载入 | 非空 HTML + token 注入成功 + **无 JS 错误** |
| 任务提交并跑完 | 出现 `完成` 且统计区有数字 |
| **图片真的加载** | 每张 `img.complete && naturalWidth > 0` |
| 任务历史 | 跑 2 个任务后列表 2 条、顺序正确 |
| **点回旧任务** | 统计区数字变成旧任务的（不是重跑）|
| 输出目录报错 | 出现**可读中文** + 焦点在输入框 |
| viewer | 点开 on → `→` 切图 → `Esc` 关 |
| 长静默文案 | 运行中且超阈值时出现「仍在工作」|

任何一条失败都会让进程退出码非零，可直接接 CI。
