**一句话结论**：达标**不需要改帧数，只需要换画布**（800×450 → 1066×600）；
代价是每张 233→407 token（**+74.7%**），因为 token 与**格子面积**挂钩，不与帧数挂钩。

### 1.1 三条约束的边际代价（本报告最重要的一张表）

**必须把「阶梯内」与「全空间」分开报** —— 混说会得出互相矛盾的结论（这是复核抓到的坑之一）。

| 范围 | 约束 | 最优组合 | 每格 | 实际短边 | 单张 token | token/帧 | 相对现状 |
|---|---|---|---|---|---|---|---|
| **阶梯内** | 现状（只 4 帧/张，800×450） | 800×450 / 4 帧 | 400×225 | 225 | 233 | 58.25 | — |
| **阶梯内** | 只要 A3-1（放开帧数） | 1066×600 / 4 帧 | 533×300 | 300 | 407 | 101.75 | **+74.7%** |
| **阶梯内** | A3-1 + A3-3（帧数 ≤4） | 1066×600 / 4 帧 | 533×300 | 300 | 407 | 101.75 | **+74.7%** |
| **全空间** | 只要 A3-1（任意画布/网格） | 1046×1500 / 10 帧 | 523×300 | 300 | 938 | 93.80 | **+61.0%** |
| **全空间** | A3-1 + A3-3（帧数 ≤4） | 1046×600 / 4 帧 | 523×300 | 300 | 392 | 98.00 | **+68.2%** |

「阶梯内」= 任务书 §技术路线 1 的四档画布 × 帧数 {1,2,4,8,16}；
「全空间」= 任意画布像素 × 任意 (cols, rows) 网格形状（`optimal_canvas` 穷举）。

**三个读法**

1. **贵的是 A3-1，不是 A3-3。** 全空间里 A3-1 单独要 +61.0%，加上 A3-3 变成 +68.2% ——
   A3-3 的边际代价只有 **4.5 个百分点**。
2. **在任务书的阶梯内，A3-3 一分钱都不花**：阶梯的帧数集合里没有 9/10 档，
   「只要 A3-1」和「A3-1+A3-3」是**同一个解**（1066×600/4）。A3-3 的代价只在放宽画布后才显形。
3. **全空间那两行的便宜是靠 2% 的格子比例容差换的**：523×300 的比例误差 1.94%。
   **若要求零变形，4 帧方案的下界就是 1066×600 / 407 token**（附 B 有推导）。

### 1.2 A3-1 与 A3-3 的真冲突（量化，不是口号）

- **A3-1 下「每张帧数」的上限是 10**（不是 9）：`1046×1500 / 10 帧 / 2×5` 每格 523×300，938 token；
  `pack ≥ 11` **穷举无合规画布** —— 画布还没大到让每格 ≥300px，就先越过 **1024 token 上限**被宿主缩小。
- 独立复核另给了一个「每格**恰好** 16:9」的例子：`2800×630 / 5×2 / 10 帧` → 每格 560×315，
  1022 token（合规，但不是最省 —— 说明「恰好 16:9」不是最省的必要条件）。
- 被 token 上限缩水的**具体机理**（可复核）：`2136×1202` 的 16 格拼图计费 968 token（看着没过 1024），
  但那是缩过之后的网格数 —— 实际送到模型手里是 **1708×952**，每格 427×238。
  这个数字用 `node` 直跑 see-now 的 `src/tokens.js` 原件对过，**逐位一致**。

立项书 §三 STATE R3 预见的冲突成立，但**不是「不可兼得」**：两者都能满足，代价 +68.2%（全空间）/ +74.7%（阶梯内）。

## 4. 反向样本原文

### 反向样本 1 · 8 帧 / 800×450 → 必须 FAIL

```
FAIL: 8-frame sheet cell = 266.7x150 px (short side 150 < 300)
REASON A3-1 FAIL: 每格短边 150px < 300px
REASON A3-3 FAIL: pack=8 > 现状 pack=4：组内邻居变多，distinct_frac 会降
```

**与任务书给的 173 不一致，以实测为准，三种口径都记在案**：

| 来源 | 8 帧 / 800×450 的每格 | 说明 |
|---|---|---|
| 任务书 §背景数字 | 400×173 | 近似值（且 400×173 与 800×450 的几何不自洽） |
| 本模块的均匀网格模型 | **267×150** | 保比例优先 → 3×3 网格（空 1 格），800/3 × 450/3 |
| **实测产物** `sheets/8帧.png` | **最小格 200×82** | 见-now 的非均匀排布：400×176 / 200×82 / 400×174，**第 8 格是纯黑空白** |

**三种数都远低于 300，FAIL 的结论不依赖用哪一个。** 实测方法可复现：把 PNG 解成灰度算相邻行列梯度 ——
y∈[0,176] 的列梯度峰值在 x≈400（2 格）；y∈[176,258] 在 x≈200/400/600（4 格）；
y∈[258,432] 右半边灰度均值 **2.2**（纯黑，第 8 格没画上）。

### 反向样本 2 · 1 帧 / 800×450 → 必须 PASS，但必须报 token 浪费

```
PASS: 1-frame sheet cell = 800x450 px (short side >= 300)
WASTE 单帧 233.0 token/帧 vs 4帧方案 101.8 token/帧 = 2.29x；
      同样 200 帧要发 200 张 vs 50 张（46600 vs 20350 token）
```

1 帧/张**确实达标**（短边 450），但每帧贵 **2.29 倍**、张数 **4 倍**。报告不许只写「达标」；
`accept_m4.sh` 里这条是**硬闸门**（`WASTE ... = 2.xx` 不出现就判 FAIL）。

### 闸门自证（R99：一个永远不会红的闸门不是闸门）

三个**实测抓到过的假绿路径**，现在都有测试钉住：

1. **`accept_line()` 曾对不达标候选输出 PASS**。旧版只看名义格子短边，于是：
   - `800×450 / 2` → `PASS: 2-frame sheet cell = 400x450 px` —— 可 16:9 的画面塞进 0.89 的格子是**变形**；
   - `2136×1202 / 16` → `PASS: 16-frame sheet cell = 534x300.5 px` —— 可实际被缩到每格 427×238。
   现在 `accept_line` 用**实际短边**（`cand.short_side`）**且**要求 `ok_aspect`
   （`test_accept_line_rejects_aspect_distortion_too` / `test_token_cap_shrink_is_not_a_pass`）。
2. **1024 token 上限缩水**：2136×1202 名义每格 534×300，实际 1708×952 → 每格 427×238。
   数字与 see-now `src/tokens.js` 用 **node 实跑**一致。
3. **比例闸门**：800×450 / 2 帧短边 400 ≥300 **看着达标**，但比例误差 0.5 → FAIL。

> ⚠️ **勘误（统筹方初版报告的一处错误）**：初版把「800×450 / 2 帧（400×450）」列为**达标组合**。
> 这是把「格子矩形的短边」当成了「画面的短边」。16:9 的帧放进 400×450 只有两种结局：
> 拉扁一倍，或上下留黑边 —— 留黑边时**画面只剩 400×225**，比现状的 225 一点没好转。
> A3-1 的本意是「模型能读清的像素」，「格」必须按画面量。所以比例是硬约束，这条组合不可行。

> ⚠️ **另一个必须披露的产物缺陷**：被当作「现状 4 帧」几何锚点的 `sheets/4帧.png`
> **第 4 格也是空白的**（实测 y228:446 × x402:800 的 **98.7% 像素恒为 0**，均值 0.88），
> 与 `8帧.png` 第 8 格（99.5% 纯 0）是同一病症 —— 这张图实际只有 3 帧有内容。
> **几何结论不受影响**（分隔线实测 x≈399 / y≈224 → 2×2 / 每格 400×225，短边 225），
> 但「现状 4 帧」这句话没有完整产物支撑，已列入 §7 决策 3。

## 7. 需要决策的事

**决策 1（主）：要不要接受 +74.7% token 换「每格 225px → 300px」？**

| 选项 | 效果 | 代价 |
|---|---|---|
| A. 保持 800×450 / 4 帧 | token 不变，A3-1 不达标（225px） | 小字/文件名读不清 |
| B. **1066×600 / 4 帧**（推荐） | A3-1 达标（正好 300px），帧数/张数/冗余全不变，**零变形** | **token +74.7%** |
| C. 1050×600 / 4 帧 | 同上，再省 3.7% | 画面被压扁 1.94%（肉眼不可辨，但不是零） |
| D. 1280×720 / 4 帧 | 达标且留 20% 余量（360px） | token +148% |
| E. 做成参数 `--canvas auto\|small\|readable` | 只在需要读字时升画布 | 一个开关 |

**建议：B 作为默认，D 作为「上游会二次缩放」时的退路，E 作为接口。**
理由：A3-1 的达标点恰好落在 1066×600，且**张数与帧数都不变** —— 这是一次纯粹的「分辨率换钱」，
风险最低、最容易回退（改一个常量）。C 的 3.7% 要拿画面比例去换，不建议做默认。

**决策 2：A3-3 的「不降」判据要不要写死成 `pack ≤ 4 且整除`？**
现状指标定义下：`pack > 4` 会让 distinct_frac 机械下降（跨 pack 比指标）；`pack < 4` 且**不整除**时
又不可比（U5，实测有倒挂）。**建议**：A3-3 只对 `pack = 4`（同口径）判定，其余 pack 一律标 UNVER
并要求额外实测证据 —— 这正是 `layout.py` 现在的实现。

**决策 3：要不要把「拼图缺格」的 bug 反馈给 see-now？**
`sheets/8帧.png` 第 8 格纯黑（99.5% 纯 0），**`sheets/4帧.png` 第 4 格也是**（98.7% 纯 0）。
后者是 A3-1 基线的锚点产物，所以这条不只是 8 帧的问题。建议登记到 see-now 的 divergence 记录里
（本模块不改 see-now 源码）。

### 附 B · 4 帧方案在**零变形**下的下界 = 407 token（可证）

token 是 42px 网格的阶梯函数：`tokens = rows × (cols + 1) + 2`。

- A3-1（短边 ≥300）∧ **画面零变形**（格子比例 = 16:9）⟹ 每格 ≥ **533.33×300**
  ⟹ 4 帧 2×2 的画布 ≥ **1066.67×600**。
- `H ≥ 600` ⟹ `rows ≥ 15`（600→602→43→⌈43/3⌉=15；rows=14 要求 H ≤ 588，与 H≥600 冲突）。
- `W ≥ 1066.67` ⟹ `cols ≥ 26`（1067→1078→77→⌈77/3⌉=26）。
- ⟹ `tokens ≥ 15 × 27 + 2 = `**`407`**，且 1066×600 恰好取到 407 ⟹ **407 是零变形下的最小值**。

> **这一步之前写错过**：旧版把「零变形」当成了代码的实际判据去用，于是漏掉了 2% 容差内的
> 1050×600/4 = 392（每格 525×300，误差 1.56%）。**代码的判据是 2% 容差，不是零变形** ——
> 所以「407 最小」只在零变形这一档成立；放宽到容差内，全局最优是 392。
> 两个数都对，只是**回答的不是同一个问题**（这正是 D-006/D-010 那类「换了度量还以为在优化」的形态）。
