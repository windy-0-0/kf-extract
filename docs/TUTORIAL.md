# 使用教程 · 从装到用

> 这份教程的每条命令都在本机跑过，输出是**实际复制**的，不是"应该这样"。
> 全部内容不需要 GPU，不需要联网，素材不出本机。

---

## 零 · 安装（一次就好）

### 需要什么

```bash
python3 --version    # 需要 3.9 或更高
ffmpeg -version      # 必须有（命令行版，不是 GUI）
```

没有 ffmpeg 的话：

| 系统 | 命令 |
|---|---|
| macOS | `brew install ffmpeg` |
| Ubuntu/Debian | `sudo apt update && sudo apt install -y ffmpeg` |
| Fedora | `sudo dnf install -y ffmpeg` |
| Windows | `winget install --id Gyan.FFmpeg` |

### 装

```bash
pip install kf-extract
```

装完验证：

```bash
$ kf-extract --version
kf-extract 0.2.5
```

> 装不上（比如公司网络屏蔽 PyPI）也可以直接跑源码：
> ```bash
> git clone https://github.com/windy-0-0/kf-extract.git
> cd kf-extract
> python3 -m venv venv && venv/bin/pip install -e .
> ```

## 一 · 最短路径（30 秒）

拿一段视频，一行搞定：

```bash
kf-extract 你的视频.mp4 --k 80
```

输出：

```
shots/
├── frame-00000.png … frame-00079.png   # 80 张原分辨率帧
├── sheet-000.jpg … sheet-019.jpg       # 20 张拼图（每张 4 帧）
├── extract.json                        # 全部数字（可复核）
└── summary.md                          # 30 秒读完的摘要
```

**第一件事：打开 `summary.md`。** 它已经把该看的排好了：

```markdown
# 关键帧抽取结果 · trailer.mp4

- 选中帧数：**20**
- 覆盖质量 maxdist：**7.632**（32×18 灰度上的 L1 均值，0–255 刻度；越小 = 盲区越小）
- 时间空白：最大 **2.0s**，中位 0.5s
- 时间覆盖：10/10 段（均匀 = 每段都有）
- 黑场：选中帧里 **1 帧近乎全黑**（全片共 9 帧黑场）
- 出图档位：readable（1066×600，每格 533×300） → 5 张图集，共 **2035 token**
- 耗时：2.2s
```

## 二 · 先问"要抽多少帧"（省时间的习惯）

**不要一上来就抽。** 先花 10 秒探测：

```bash
$ kf-extract 你的视频.mp4 --probe

trailer.mp4  14s / 84 帧 @6.0fps
动作强度: 相邻帧平均 L1 = 4.33  →  档位 **中高**（有明显运动）
粗估: 每 1~3 秒一帧（粗略参考，非承诺值）

    预算      最少帧数       每几秒一帧    打包 token
    40         3        4.7s         407
    30         4        3.5s         407
    20         6        2.3s         814
```

**怎么读这张表**：

- **预算** = 你能接受的最大盲区（0–255 灰度刻度，越小越严）
- **最少帧数** = 达到那个盲区至少需要几帧
- **打包 token** = 拼成图集后送给模型要花多少

**为什么这一步重要**：同样的预算，不同素材的帧数差得极远。实测：

| 素材 | 预算 30 → 需要几帧 | 每几秒一帧 |
|---|---|---|
| 编程录屏（画面几乎不动）| **5 帧** | 53 秒 |
| 真人 Vlog（说话为主）| 45 帧 | 11 秒 |
| 动画 MV（大量运动）| 194 帧 | 1.2 秒 |
| 街拍跟拍（帧帧不同）| **261 帧** | 0.8 秒 |

**同样是"预算 30"，最少 4 帧、最多 261 帧（65 倍）。** 不先探一下就抽，很容易抽多或抽少。

探完之后挑一档：

```bash
kf-extract 你的视频.mp4 --budget 30     # 自动决定 K
```

## 三 · 三个旋钮怎么调

### `--k` 抽多少帧

| K | 适合 |
|---|---|
| 40 | 粗看剧情 |
| **80** | **推荐起点** |
| 160 | 细看 |
| 320 | 逐镜研究 |

**K 翻倍，覆盖质量只提升约 10%** —— 边际很低，所以"加一倍"通常不划算。

> ⚠️ **但 K 不是越大越好，会翻车**。14 秒的短视频实测：
> K=8 → 拼图内 100% 格子真不同；K=16 → 75%；**K=32 → 只有 28.1%**。
> 原因：短素材帧数少，K 一高就会把同一镜头的相邻两帧都选进来。
> **经验法则：K ≈ "你想要的画面数量"，不是"你想看多少帧"。**

### `--balance` 时间均衡（默认 0.2）

| 值 | 覆盖代价 | 空白降幅 |
|---|---|---|
| `0` | 0% | 0%（会留长空白，实测番剧最长 **196.7 秒**）|
| **`0.2`（默认）** | **+1.4%** | **−32%** |
| `0.3` | +3.0% | −30.6% |
| `0.5` | +24.7% | −58% |

**0.2 和 0.3 怎么选**：0.2 覆盖更省，但 0.3 在「高变化集中在某段」的素材上更稳
（`fanren184` 实测：0.3 的空白 47.2s，0.2 是 78.0s）。拿不准就用默认 0.2。

### `--canvas` 出图档位

| 档 | 画布 | 每格 | token/张 | 什么时候用 |
|---|---|---|---|---|
| `cheap` | 800×450 | 400×225 | 233 | 只看画面，不读字 |
| **`readable`（默认）** | 1066×600 | 533×300 | 407 | 要读清小字/字幕 |
| `max` | 1280×720 | 640×360 | 578 | 要看清细节 |

**默认取 readable 是实测的**：同一批帧，400×225 平均认出 10.5 个字，
533×300 认出 17.0 个字（**+62%**），而 token 只多 75% —— 边际约 1:1，值。

## 四 · 长素材：中断与续跑

29 分钟的番剧要跑 **85 秒**。这 85 秒里你随时可能按 Ctrl-C。

### 按键之后会怎样

```bash
$ kf-extract 番剧.mp4 --k 80
  · 解码完成 已解码 10403/10403 帧
  · 选帧完成
^C
已停止（SIGINT）。已导出的帧保留在 shots/，加 --resume 可接着跑。
$ 
```

- **响应 0.02 秒**（不是"等一下才停"）
- **退出码 130**（不是 0，脚本不会误判成功）
- **已解出的部分存成了缓存**

### 接着跑

```bash
kf-extract 番剧.mp4 --k 80 --resume
```

实测：解码阶段 **55.8s → 0.0s**（直接复用缓存）。

### 改了参数再跑

```bash
kf-extract 番剧.mp4 --k 120 --out 同一个目录 --resume
```

参数一变，缓存**自动失效并重算**——不会拿旧结果冒充新的。

### 真的崩了（拔电 / 强杀）怎么办

```bash
$ kf-extract --recover
已把 1 条「运行中」标成「已中断」（上次退出时没跑完）:
  fanren184.mp4  停在 decode 32%  → shots
```

然后照它说的续跑。**部分解码的帧会被复用，不用从头解**
（实测：全片 55.1s → 从 32% 处续解 40.3s）。

$ kf-extract --history

11-07 19:20:46   trailer.mp4              done        k=20           2.6s
11-07 18:12:03   fanren184.mp4            interrupted  ⏸k=80         31.5s

## 六 · 图形界面（不想敲命令的话）

```bash
kf-extract --gui
```

浏览器自动打开。能做四件事：

### 1. 选素材 + 三个旋钮 + 开始

只列出本地视频。默认只扫项目目录 —— 想加别的目录：

```bash
kf-extract --gui --dirs ~/Movies,~/Downloads
```

### 2. 输出目录

留空 = 素材旁的 `shots/`。填了会记住，下次还在。

**只允许家目录或项目目录之下**（防止误写到系统目录）。填 `/etc/shots` 会告诉你：

```
输出目录不可用：输出目录必须在 /Users/你 或 /你的项目 之下。
你给的是 /private/etc/shots
```

### 3. 看结果 + 放大看图

跑完直接出图集和单帧。**点任意一张图可以放大**：

- `+` / `−` 缩放，滚轮也行
- `1:1` = **按原始像素显示**（1066 宽的图会自动放大 1.2×，不是"缩放 1.0"）
- `←` `→` 切图，`Esc` 关闭

### 4. 批量跑一堆

勾「批量（可多选）」→ 勾选视频 → 开始。每个视频输出到**独立子目录**，不会互相覆盖。

进度是**整批聚合**：`批量：1/2 完成 · 1 在跑` → `全部完成（2/2）`。

## 七 · 把自己的抽取嵌到代码里

```python
import kf

r = kf.extract('番剧.mp4', k=80, out='shots/')

print(r.selected_k)        # 抽了几帧
print(r.maxdist)           # 覆盖质量（越小越好）
print(r.max_gap_sec)       # 最大时间空白
print(r.keys_time_sec)     # 每帧的时间戳，可以直接对回视频

r.save('报告.json')        # 存成 JSON
print(r.summary())         # 生成 summary.md 的文本
```

**只要数字不要文件**：

```python
r = kf.extract('番剧.mp4', k=40)     # 不传 out
print(r.maxdist, r.selected_k)       # 不写任何文件
```

**接进度条**：

```python
def prog(stage, frac, msg):
    print(f'{stage} {frac*100:.0f}% {msg}')

kf.extract('番剧.mp4', k=80, progress=prog)
```

## 八 · 怎么判断结果好不好

抽完了，看三个数就够了：

### ① `maxdist` —— 覆盖质量

> "任意一帧到离它最近的选中帧，最远有多远"

**越小越好**。它回答的问题是：**这段视频有没有哪一段我完全没看到？**

参考量程（0–255 灰度刻度）：

| maxdist | 含义 |
|---|---|
| < 10 | 覆盖得很密 |
| 10–30 | 正常 |
| 30–50 | 有盲区，但可接受（长番剧常见）|
| > 60 | 盲区很大，考虑加 K |

### ② `max_gap_sec` —— 最大时间空白

> 相邻两张关键帧最多隔多久

**越小越好**。它回答的问题是：**会不会跳过一段剧情？**

番剧这类长素材，`--balance 0` 会留下接近 200 秒的空白（等于跳过三分钟）。

### ③ `token 合计` —— 花了多少

拼成图集后的总 token。20 张 × 407 = 8140。

**省 token 的原理**：一张 1066×600 装 4 帧 = 407 token，
而 4 帧各自 1920×1080 = 3872 token —— **省 89.5%**。

## 九 · 遇到问题

### "找不到 ffmpeg"

退出码 3，并打印三个平台的安装命令。装完直接重跑，不用重装本工具。

### "选中的帧里有一堆全黑"

正常的。黑场转场确实"和别处都不一样"，算法会选它。
工具会告诉你几帧，不会偷偷删掉（因为整段夜景的片子，黑就是内容本身）。

### "摘要里说『连续静止 200 秒』"

**这说明这段素材画面几乎不变**（录屏、PPT、长定格）。那不是错误，是如实报告。

**但要小心一种情况**：画面里只有**小面积缓慢变化**（字幕、光标、进度条）时，
像素度量测不出来（这是纯像素方法的物理上限，已实测确认）。
所以警告后面有个按钮「看这段附近的关键帧」—— **点一下直接跳到那帧，自己看一眼**。

### "我按了 Ctrl-C，输出目录里还有半截文件"

正常。已拿到的帧会保留（这是设计）。加 `--resume` 接着跑，或删掉目录重来。

### "想确认不用 GPU、不联网"

对。纯 CPU、纯本地，素材不出本机。唯一的外部依赖是 ffmpeg。

## 十 · 命令速查

```bash
# 装
pip install kf-extract

# 最常用
kf-extract 视频.mp4 --k 80

# 先探成本
kf-extract 视频.mp4 --probe

# 按盲区预算抽
kf-extract 视频.mp4 --budget 30

# 要读清小字
kf-extract 视频.mp4 --k 80 --canvas readable

# 不留长空白
kf-extract 视频.mp4 --k 80 --balance 0.3

# 中断后接着跑
kf-extract 视频.mp4 --k 80 --resume

# 看跑过什么 / 崩溃后恢复
kf-extract --history
kf-extract --recover

# 图形界面
kf-extract --gui

# 只要图集不要单帧（省磁盘）
kf-extract 视频.mp4 --k 80 --no-images

# 打包产物
kf-extract 视频.mp4 --k 80 --zip
```

## 附 · 它不做什么

- ❌ **不做实时** —— 离线工具
- ❌ **不做语音/字幕理解** —— 只处理画面
- ❌ **不做"原画帧"精确检测** —— 实测做不到（成片里几乎没有完全相同的相邻帧）
- ❌ **不需要 GPU**
- ⚠️ **看不见小面积缓慢变化**（字幕/光标）—— 已知限制，会如实警告并给出跳转按钮
