# M1 设计 · k-center 关键帧抽取器

> 前置：M0 基线已钉死（`docs/status/M0-baseline.md`）。
> 验收：立项书 §三 A1 / A2。

---

## 一句话

**不追「画面变了」，追「画面被覆盖了」。**

给定预算 K 张图，选出 K 帧，使「任意一帧到离它最近的关键帧」的最大距离最小。
这是 **facility location / k-center** 问题；朴素贪心（最远优先）是 2-近似，对本场景够用。

---

## 为什么不是「变化筛选」

| | 变化筛选（see-now） | 覆盖筛选（本方案） |
|---|---|---|
| 优化的量 | 「相邻帧差多少」 | 「整段最长盲区多大」 |
| 对运动 | 敏感（运动会算成变化） | 不敏感（只要运动段内有一帧就够） |
| 离线结果（实测） | 拼图内 **86%–99% 重复** | 目标 ≥70% 不重复 |
| 计算成本 | O(N)（每帧一次差分） | O(K·N·D) |

代价是更贵，但离线场景**一次过**，可接受。

---

## 算法

```
输入：X[1..N][D]（32×18 灰度展平，D=576），预算 K，或覆盖预算 budget
输出：K 个帧下标

最远优先贪心：
  keys = [0]
  d[i] = L1(X[i], X[0])          # 每个帧到「已选集合」的最近距离
  repeat K-1 次：
      j = argmax(d)               # 最没被覆盖的那一帧
      keys.append(j)
      d[i] = min(d[i], L1(X[i], X[j]))
  return keys

「给定预算最少几帧」= 边加边判 d.max() <= budget（D-008：单调，不需要二分）
```

**复杂度**：O(K·N·D)。30min @6fps（N=10403, D=576），K=300 实测 **1.8s**。

---

## 三个必须做的工程决定

### 1. 距离度量必须能反映「这张图有没有新信息」

朴素 L1 对**大幅平移**敏感：同一个人往右走两步，L1 会很大，但它不是新信息。
所以 M3（光流预处理）要把它作为**距离度量**改进，而不是独立检测器：
用「光流 warp 后的残差」代替原始 L1。**但 M3 未验证前，M1 先用原始 L1**（不依赖未验证假设）。

### 2. 分块 + 内存上限

`maxdist` 必须自适应 chunk（D-011）：`chunk = 100MB / (K·D·4)`。
否则 K=1200 时固定 chunk=256 吃 707MB。

### 3. 输出必须带「覆盖质量」自证

每次抽取都要报告：
- 选了几帧
- `maxdist`（最大盲区）
- 每个关键帧的「它覆盖了多少帧」（= 到它最近的帧数）

**没有这三个数字的抽取结果不许采信**（否则无法和基线比较）。
