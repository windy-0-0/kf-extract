你是 **M4（出图策略）负责人**。一句话目标：
给定 K 个关键帧，决定 **每张拼图放几个帧、每个格子多大**，使「模型读图的信息量」最大，

## 背景数字（别自己重测，直接用）

| 事实 | 数值 | 出处 |
|---|---|---|
| 800×450 一张 ≈ | **233 token** | see-now README（14px patch，42px 网格） |
| 1280×720 一张 ≈ | **578 token** | 同上公式 |
| 4 帧/张 → 每格 | 400×225 | 实测（`sheets/4帧.png`） |
| 8 帧/张 → 每格 | 400×173 | 实测（`sheets/8帧.png`） |
| 真实番剧拼图内「真不同」占比 | **50.9%（pack4）/ 48.9%（pack8）** | D-012 |

**核心张力**：帧数多 → 一张图覆盖时段长，但每格变小（小字/细节丢失）；
帧数少 → 每格大，但要多发几张（token 线性增长）。

## 必须先量账（不许跳过）

先回答一个可测的问题，再谈设计：

> **同一段 30 秒画面，用「8 张单帧大图」vs「2 张 4 帧小图」vs「1 张 8 帧更小图」，
> 模型哪一份能读对更多细节？**

你没有模型，所以用**代理指标**：
1. **可读性代理** = 每格短边像素（A3 硬门槛 300px）。
2. **信息量代理** = `metrics.redundancy()` 的 `distinct_frac`（越高越不浪费格子）。
3. **成本** = 张数 × 每张 token。

把这三条做成一张表，跑 4 段素材，**先出表再设计**。

## 验收（外部锚点）

### A3-1 · 每格短边 ≥ 300px

`bash scripts/accept_m4.sh` 必须输出：

```
PASS: 4-frame sheet cell = XXXxYYY px (short side >= 300)
```

**注意**：800×450 放 4 帧只能给 400×225（短边 225 < 300）。
**所以达标必须换画布尺寸或减帧数** —— 这就是要算的地方。

### A3-2 · 代价必须量化

必须给出：达到 A3-1 后，**同一段素材要发几张图、总 token 多少**，
和「现状（4 帧/张 800×450）」相比的增减。

### A3-3 · 不许牺牲 A2

`distinct_frac` 不许比现状**降低**（现状：真实番剧 pack4 = 50.9%）。
若降低 → FAIL。

### 反向样本（缺一不算过）

1. 构造「8 帧 800×450」→ 必须报 FAIL（短边 173 < 300）。
2. 构造「1 帧 800×450」→ 必须 PASS 但**报告 token 浪费**（张数暴涨）。

## 允许的技术路线

1. **画布尺寸阶梯**：800×450 / 1066×600 / 1280×720 / 1600×900 × 帧数 1/2/4/8/16，
   穷举全表，用「每格短边 ≥300 ∧ distinct_frac 不降」筛出可行组合，再按 token 排序。
2. **非均匀格子**：高信息帧给大格、静态帧给小格（借用 `see-now/src/pack.js` 的 DP 装箱思路，
   Apache-2.0，可抄算法但**必须保留 NOTICE**）。
3. **两张一组**：前一半帧一张、后一半一张，避免极密拼图。

**禁止**：引入新运行时依赖（本期只用 numpy + 标准库 + ffmpeg）。
